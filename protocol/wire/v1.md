# Cura Agrorum Wire Protocol v1

This document defines the transport envelope used to carry one or more typed
events in a single frame. Payload schemas such as `reading_t` are defined
separately in `protocol/schemas/`.

## Names

- **Frame**: transport-level TCP length prefix plus the envelope body.
- **Envelope**: the frame body containing one or more events.
- **Event**: one typed payload with its own record type, schema version, and
  payload length.

## Byte Order

All frame, envelope, and event header fields are unsigned integers encoded in
network byte order.

Payload byte order is defined by the payload schema.

## Frame

```text
u32 body_len
u8  body[body_len]
```

`body_len` is the number of bytes after the 4-byte frame length field. It does
not include the frame length field itself.

The TCP receiver reads exactly 4 bytes for `body_len`, validates it against the
implementation's maximum accepted frame size, then reads exactly `body_len`
bytes for the envelope body.

## Envelope Body

```text
u16 envelope_version
u16 event_count
event[event_count]
```

`envelope_version` must be `1` for this wire protocol.

`event_count` is the number of events encoded in the envelope. Version 1
envelopes must contain at least one event.

## Event

```text
u8 record_type
u8 schema_version
u16 payload_len 
u8  payload[payload_len]
```

`record_type` identifies the logical payload type, such as a sensor reading.

`schema_version` identifies the payload schema version for `record_type`.

`payload_len` is the number of payload bytes following this event header. It
does not include the 4-byte event header.
